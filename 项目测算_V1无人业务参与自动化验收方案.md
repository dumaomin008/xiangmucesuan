# 五、测试环境隔离

自动化测试必须使用独立测试数据。

禁止：

``` text
直接使用开发数据库
直接删除真实项目
依赖已有数据库中的某条记录
```

推荐：

``` text
DATABASE_URL = test database
```

每个测试 Scenario：

``` text
Before
→ 创建测试数据

After
→ 清理测试数据
```

或整个 Suite 使用独立临时 DB。

测试必须：

``` text
可重复运行
与执行顺序无关
不依赖人工预置数据
```

## Scenario 08：Snapshot / Version / Copy / Compare

完整链路：

``` text
创建方案 A
→ 运价 X
→ 正式测算 A1
→ 保存 Snapshot A1
→ 修改方案 A 运价为 Y
→ 正式测算 A2
→ 打开 A1
→ A1 结果必须保持不变
→ 复制方案 A 为方案 B
→ 修改 B 参数
→ 正式测算 B
→ A 与 B 对比
→ 设置基准
→ 查看历史版本
```

验证：

``` text
A1 != A2
A1 再次打开 == 原 A1
B 不带 A 的 CalculationResult
B 不带 A 的 Snapshot
A/B 子资源 ID 不同
基准唯一
```

# 二十七、如果测试发现 BUG

处理方式：

``` text
自动化测试发现
→ 先记录失败 Case
→ 确认是代码 BUG
→ 最小范围修复
→ 增加 Regression Test
→ 重跑整个 Acceptance
```

禁止：

``` text
为了让测试通过修改 expected
为了让测试通过删除 Case
skip
only
降低断言
```

如果发现属于 BUSINESS 待确认口径：

``` text
不要改业务公式
→ 标记 BUSINESS
→ 保持当前 V1
```

除非它会导致系统无法正常使用，否则 BUSINESS 项不阻塞技术封版。
