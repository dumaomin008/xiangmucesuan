## 2. Context 状态

### 2.1 已确认事实

- 产品属于新能源重卡业务经营管理平台。
- 核心视觉参考来自一组企业级安全/SASE 管理平台截图，共 19 张。
- 参考覆盖 Dashboard、列表、详情、表单、弹窗、导航、拓扑、流程、帮助与异常页面。
- 参考图的页面设计风格可以作为平台主要视觉依据。

### 2.2 已确认设计决策

- 目标气质：专业可信、克制精致、高信息密度、轻科技、数据驱动、行动导向。
- 保留参考系统的布局秩序、导航层级、表格密度、状态体系、弱边框、轻阴影和小圆角。
- 将突出“安全”的行业元素系统性替换为新能源、车辆、重卡、充电、换电、线路和能源场站元素。
- 业务界面不使用紫色、Violet、Lavender 或 Magenta 作为品牌、导航、状态、Avatar、Badge、进度和装饰色。
- 不做传统模板化后台，不做炫酷数据大屏，不依靠大面积渐变、玻璃拟态或重阴影制造高级感。
- 优先通过排版、空间、对齐、真实业务数据和完整交互状态建立完成度。
- Dashboard、项目列表、项目详情为第一批基准页面；验证通过后再推广到其他模块。

### 2.3 当前假设

- 产品以桌面端企业用户为主要使用者。
- 高频场景包含查看经营结果、推进项目、识别风险、处理待办、追踪合同/交付/运营状态。
- 平台需要承载中高信息密度和真实业务数据。

以上假设需要在真实项目 Context 中验证，不得自动升级为业务需求。

## 3. 设计定位

### 3.1 目标方向

**经营智能 + 项目推进型企业平台**

界面应帮助用户快速回答：

1. 当前经营结果如何？
2. 项目推进到了哪里？
3. 哪些合同、车辆、线路或场站存在风险？
4. 现在最需要处理什么？

### 3.2 设计关键词

- 企业可信
- 经营清晰
- 结构稳定
- 信息紧凑
- 状态可扫描
- 数据可解释
- 操作可追踪
- 轻量新能源语义

### 3.3 非目标

- 不追求展示型大屏效果。
- 不追求营销页式视觉冲击。
- 不将“科技感”等同于发光、网格、深色霓虹或大面积渐变。
- 不将所有信息包装成卡片。
- 不使用与业务无关的装饰图表或图标。

## 4. 核心设计原则

### 4.1 内容先于容器

优先使用字号、字重、间距、分组和背景层级组织内容。只有独立语义、可交互选择或需要与周围内容隔离时才使用 Card。

### 4.2 业务状态先于视觉装饰

颜色、图标、Badge 和图表必须表达业务含义。没有明确语义的元素不得仅为“丰富页面”而增加。

### 4.3 第一屏形成决策闭环

Dashboard 与详情页首屏必须同时提供：现状、风险、下一行动。不能只展示数据而不支持判断和推进。

### 4.4 高密度但不拥挤

通过稳定栅格、明确对齐、低噪声边框和层级字体容纳复杂内容。不可简单缩小字号或压缩点击区域换取密度。

### 4.5 异常优先于正常

用户应先看到需要关注、阻塞、超期或失败的内容。正常状态保持低视觉权重。

### 4.6 先复用，后扩展

新页面优先复用现有 Token、组件与最接近的业务 Pattern。只有现有组件不能满足已确认需求时才新增组件。

复用指组件结构、行为和可访问能力，不代表必须继承与本规范冲突的视觉值。如果现有主题以紫色为主，应将现有组件映射到本规范的蓝色、绿色和中性色 Token，而不是继续扩散紫色。

### 4.7 单一主表达

同一业务事实只能有一个主要视觉表达位置。允许在导航或上下文中出现一次弱化提示，但不得在同一屏幕反复强调。

- 当前阶段：以阶段组件为主要表达；Header 仅在必要时显示简短状态，不重复百分比和完整阶段名。
- 项目风险：以风险状态或阻塞区域为主要表达；不得同时出现在多个彩色 Tag、摘要格和提示条中。
- 下一行动：以一个主要行动区或主按钮表达；其他位置只提供上下文链接。
- 车辆规模、合同金额、投运日期等事实：在摘要区表达一次，正文仅在需要编辑或追溯时再次出现。

### 4.8 视觉忠实度优先

本规范的视觉参考优先于 Codex 默认生成习惯。不得将页面自动转换为常见的紫色 AI SaaS、渐变卡片或通用 shadcn 风格。

当文字规范与参考截图可能产生多种解释时，应优先匹配参考截图中的：

1. 页面骨架与导航比例。
2. 内容密度与留白节奏。
3. 蓝、绿、中性色关系。
4. 小圆角、弱边框和低阴影。
5. 表格、详情区和状态表达方式。

## 5. 行业语义转换

参考系统的结构可以继承，但行业语义必须转换：

| 安全/SASE 语义 | 新能源重卡平台语义 |
|---|---|
| 安全态势 | 经营态势 / 运营态势 |
| 安全健康度 | 项目健康度 / 运营健康度 |
| 告警中心 | 经营风险 / 异常中心 |
| 攻击链路 | 项目推进链路 / 交付履约链路 |
| 终端设备 | 新能源重卡 / 车辆 |
| 操作系统分类 | 品牌 / 车型 / 能源类型 |
| 网络拓扑 | 项目—线路—车辆—场站—能源关系 |
| 在线 / 离线 | 运营中 / 停运 / 维修 / 待交付 |
| 风险等级 | 项目风险 / 履约风险 / 运营风险 |
| 软件分布 | 车型 / 区域 / 线路 / 能源结构分布 |
| 安全策略 | 经营策略 / 运营规则 |
| 病毒或故障分析 | 能耗 / 故障 / 出勤 / 运营异常分析 |

不得只替换名称和图标。每个转换后的模块都必须重新确认指标口径、状态来源、下钻路径和操作权限。

## 6. Design Tokens

以下 Token 是基于参考截图推导的 V1.1 建议值。若真实项目已有 Token，应优先映射到现有体系，不得并行创建第二套重复 Token。现有 Token 的结构可以复用，但与本规范冲突的紫色等视觉值必须重新映射。

### 6.1 色彩

#### 基础色

| Token | 建议值 | 用途 |
|---|---:|---|
| `color.bg.canvas` | `#F5F7FA` | 页面背景 |
| `color.bg.surface` | `#FFFFFF` | 主内容面 |
| `color.bg.subtle` | `#F8FAFC` | 筛选区、次级分组 |
| `color.bg.selected` | `#EAF2FF` | 选中或激活背景 |
| `color.text.primary` | `#1F2937` | 标题、核心数据 |
| `color.text.secondary` | `#4B5563` | 正文、表格内容 |
| `color.text.tertiary` | `#8A94A3` | 辅助信息 |
| `color.text.disabled` | `#B8C0CC` | 禁用文字 |
| `color.border.default` | `rgba(51, 52, 68, 0.15)` | 常规控件与容器边框 |
| `color.divider.subtle` | `rgba(51, 52, 68, 0.08)` | 卡片内部分隔、弱结构线 |
| `color.table.divider` | `#EDF0F4` | 表格表头及数据行横向分隔线 |
| `color.border.strong` | `#CBD3DF` | Hover、强调边界 |

#### 品牌与操作色

| Token | 建议值 | 用途 |
|---|---:|---|
| `color.brand.primary` | `#3478F6` | 主操作、当前状态、链接 |
| `color.brand.hover` | `#2467E8` | Hover |
| `color.brand.active` | `#1858CF` | Active |
| `color.brand.subtle` | `#EAF2FF` | 浅色品牌背景 |
| `color.energy.primary` | `#22B573` | 新能源、运营正常、正向表现 |
| `color.energy.subtle` | `#E8F8F0` | 新能源浅背景 |

蓝色承担操作和信息聚焦；绿色承担新能源品牌辅助与正向业务状态。绿色不得同时承担普通链接或无语义装饰。

#### 颜色白名单

业务界面只能从以下类别选色：

- 中性色：白、冷灰、深灰文字。
- 品牌/操作色：本规范定义的蓝色系列。
- 新能源辅助色：本规范定义的绿色系列。
- 业务状态色：绿色、橙色、红色、蓝色和灰色。
- 数据可视化扩展色：仅在同一图表确实需要区分多个数据系列时使用，并必须由图表 Token 集中定义。

不允许页面组件自行增加新的品牌色或硬编码任意色值。

#### 紫色禁用规则

Purple、Violet、Lavender、Magenta 和蓝紫渐变默认禁止。

禁止用于 Logo 占位图、导航激活、Avatar、用户缩写、团队成员圆点、阶段百分比、项目状态、进度条、Badge、Tag、Button、链接、图标底板、Card、边框、阴影和装饰。

只有未来正式品牌规范明确批准后，才能通过新的设计决策解除该限制。不得因为现有模板或组件库默认使用紫色而继续保留。

#### 颜色使用比例

单个典型业务页面建议遵循：

- 约 90%：白色与中性色。
- 约 7%：品牌蓝，用于交互、选中和当前状态。
- 约 3%：绿色、橙色、红色，用于真实业务状态。

一个局部区域内通常只允许一个主强调色。多个状态同时出现时，正常和非关键状态应降低视觉权重。

#### 状态色

| Token | 建议值 | 含义 |
|---|---:|---|
| `color.status.success` | `#22B573` | 正常、完成、达标 |
| `color.status.warning` | `#F59E0B` | 待关注、临期、偏差 |
| `color.status.danger` | `#EF4444` | 阻塞、超期、故障、高风险 |
| `color.status.info` | `#3478F6` | 进行中、待推进、信息 |
| `color.status.neutral` | `#8A94A3` | 未开始、关闭、无效 |

状态不得只依靠颜色表达，必须至少同时提供文字；高风险场景可增加图标。

### 6.2 字体

优先使用项目现有字体。未定义时建议：

```text
font.family.sans = system-ui, -apple-system, BlinkMacSystemFont,
                   "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif
```

| Token | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| `font.display.sm` | 28 / 36 | 600 | 核心经营数字、特殊页面标题 |
| `font.heading.page` | 20 / 28 | 600 | 列表页与管理页标题 |
| `font.heading.object` | 26 / 35 | 600 | 项目、客户等对象详情标题 |
| `font.heading.section` | 16 / 24 | 600 | 模块标题 |
| `font.heading.subsection` | 14 / 22 | 600 | 子模块标题 |
| `font.body.md` | 12 / 20 | 400 | 常规正文、表格、卡片内容 |
| `font.body.sm` | 11 / 18 | 400 | 辅助内容、次级说明 |
| `font.label` | 10 / 16 | 500 | Label、Badge、图表辅助文本 |

约束：

- 网页端字号统一使用 CSS px，不将 Sketch 数字自动换算为 pt。
- 常规业务正文、表格正文、卡片内容以 12px 为基础字号。
- 辅助正文可使用 11px，但不得承担关键业务信息。
- 10px 是非数字文字的绝对下限，仅限 Label、Badge、时间、单位、数据来源和图表辅助文字。
- 除纯数字内容外，任何中文、英文、标点或混合文字都不得低于 10px。
- 纯数字内容如图表刻度、角标计数可根据密度单独处理，但仍需在浏览器 100% 缩放下清晰可辨。
- 核心数字使用等宽数字特性时，应确保字体支持 `tabular-nums`。
- 不通过大量加粗制造层级；同一模块内一般不超过三种字重。
- 字号和点击目标必须以浏览器 100% 缩放下的实际 CSS 值验证；不得根据经过浏览器缩放的截图推断实际字号是否过小。
- 项目阶段图例、漏斗阶段名称与数值、项目排行、车辆类型图例及车辆排行统一使用 12px；图表表头、来源和低优先级辅助说明可使用 10px。
- 摘要指标单位不得与核心数字同字号同字重：常规摘要使用 12px/400，紧凑详情摘要使用 10px/400。
- 资料卡中已上传文件名使用 14px/600；文件大小、上传人和上传时间使用 11px/400。

### 6.3 间距

采用 4px 基础单位，8px 为主要节奏：

| Token | 值 |
|---|---:|
| `spacing.xs` | 4px |
| `spacing.sm` | 8px |
| `spacing.md` | 12px |
| `spacing.lg` | 16px |
| `spacing.xl` | 24px |
| `spacing.2xl` | 32px |
| `spacing.3xl` | 40px |

使用建议：

- 图标与文字：8px。
- 同组控件：8–12px。
- 表单字段：16px。
- 模块内部：16–24px。
- 页面模块：24px。
- 页面水平内边距：桌面 24px；宽屏可为 32px。

### 6.4 圆角

| Token | 值 | 用途 |
|---|---:|---|
| `radius.control` | 4px | 输入框、Button、Tag |
| `radius.card` | 8px | 常规 Card、选择卡 |
| `radius.panel` | 8px | 页面模块 |
| `radius.modal` | 10px | Modal、Drawer 内部容器 |
| `radius.full` | 999px | 圆点、Avatar、明确的胶囊状态 |

禁止将所有组件统一为 12–20px 大圆角。

### 6.5 边框与阴影

```text
border.default = 1px solid color.border.default
border.divider = 1px solid color.divider.subtle
border.table   = 1px solid color.table.divider
border.focus   = 1px solid color.brand.primary

shadow.card  = 0 1px 2px rgba(15, 23, 42, 0.04)
shadow.float = 0 8px 24px rgba(15, 23, 42, 0.10)
shadow.modal = 0 16px 48px rgba(15, 23, 42, 0.18)
```

- 常规内容区优先使用背景和边框，不默认加阴影。
- 阴影只用于需要表达高度差的浮层、Popover、Dropdown、Modal。
- 不使用彩色阴影。
- 表格数据行横线使用 `color.table.divider`，视觉强度必须低于输入框、卡片和面板边框。

### 6.6 控件高度

| Token | 值 | 用途 |
|---|---:|---|
| `control.height.sm` | 28px | 紧凑筛选、表格工具 |
| `control.height.md` | 32px | 默认企业后台控件 |
| `control.height.lg` | 40px | 关键表单、独立服务页 |
| `table.row.compact` | 40px | 高密度数据表 |
| `table.row.default` | 48px | 含副标题、状态或头像的表格 |

## 7. 页面框架与栅格

### 7.1 桌面端框架

- 顶部全局导航：56px。
- 左侧展开导航：208–224px。
- 左侧收起导航：56–64px。
- 页面内容水平内边距：24px；超宽屏可为 32px。
- 主内容区最大宽度不强制锁死，数据表与复杂详情应充分使用横向空间。
- 内容区使用 12 列栅格；列间距建议 16–24px。

### 7.2 导航层级

```text
全局业务域
→ 当前模块
→ 页面 / 对象
→ 当前 Tab / 视图
```

- 顶部导航只放稳定的一层业务域。
- 左侧导航承载当前业务域内的功能，不复制顶部导航。
- 页面内部最多保留一层主 Tabs；如必须出现二级 Tabs，应降低视觉权重。
- Breadcrumb 用于定位，不替代页面标题。
- 左侧导航收起后必须保留 Tooltip 和明确的当前状态。

### 7.3 页面标题区

页面标题区包含：

- 标题。
- 一句必要的页面说明，可选。
- 主操作，最多一个。
- 次操作或更多菜单。
- 必要时包含统计周期、数据更新时间或权限提示。

标题区不得再套一张无意义的大 Card。

### 7.4 页面容器预算

为了避免“Card 套 Card”的 AI 原型感，页面必须遵循容器预算：

- 项目详情首屏中，带完整边框和圆角的一级内容容器最多 2 个，不包含导航、表格本身和真正的异常提示。
- 同一个一级容器内不得再嵌套视觉上等价的 Card；子内容使用标题、留白、分隔线、浅灰分区或表格组织。
- Header、Breadcrumb、对象身份区、Tabs 导航本身默认不使用独立 Card。
- 连续展示的事实字段使用紧凑描述行或分栏，不为每个字段创建独立卡片。
- 同一视口内不应出现超过 3 种容器样式。
- 同一页面不应让所有模块都拥有相同圆角、边框、背景和高度。

如果移除某个 Card 后仍能通过标题、对齐和间距理解内容，该 Card 必须移除。

### 7.5 页面横向资源

- 不因视觉对称强制所有摘要列等宽。
- 当前阶段、风险和下一行动可以获得更高宽度；短数字事实使用紧凑列。
- 同时存在全局导航和对象/子项目导航时，应验证 1440px 宽度下主内容仍有足够空间。
- 第二侧栏仅在跨项目切换是高频任务时常驻；否则改为可收起导航、Popover 或返回列表路径。

## 8. 图标与行业视觉资产

### 8.1 图标原则

- 优先使用项目现有图标库；不得混用多套风格。
- 常规操作图标建议 16px；导航图标建议 18–20px。
- 图标保持线性或简洁面性风格，不使用 Emoji。
- 删除、提交、审批等高风险操作不得仅依靠抽象图标。
- 图标必须有可访问名称或 Tooltip。
- 不得自动生成字母 Monogram、紫色圆角方块或其他临时 Logo 作为正式品牌视觉。
- 未提供正式 Logo 时，使用中性文字标识或项目中已有品牌资产，不自行创造品牌图形。
- 需要通过本地文件直接预览的原型，关键业务图标优先使用内嵌 SVG 或可验证的相对路径资源；不得依赖在 `file://` 环境下可能被浏览器拦截的外部 CSS Mask。
- 同一统计卡中的图标底板尺寸、图形尺寸和语义色保持一致；图标丢失时不得以空色块作为降级结果。

### 8.2 行业图形词汇

优先建立以下图形资产：

- 新能源重卡、牵引车、自卸车等已确认车型。
- 单车、车队、司机、客户、项目。
- 运输线路、起点、终点、里程、运量。
- 充电桩、换电站、能源场站、电池、电量、补能。
- 合同、评审、交付、投运、结算。
- 故障、维修、停运、超期、阻塞。

不得继续使用盾牌、病毒、攻击、服务器、操作系统等安全行业符号，除非具体功能本身确实需要。

## 9. 通用组件规范

### 9.1 Button

- Primary：页面唯一主任务。
- Secondary：次级操作。
- Text / Ghost：低频或上下文操作。
- Danger：破坏性操作，仅在明确确认后使用。
- 同一可视区域尽量只有一个视觉最强的 Primary Button。
- 按钮文案使用“动词 + 对象”，如“新建项目”“提交评审”。

### 9.2 Input、Select 与表单

- 默认使用上方 Label，复杂密集筛选可使用左侧 Label。
- Placeholder 只作示例，不替代 Label。
- 必填、说明、错误应与字段保持稳定位置。
- 表单必须具备 Default、Hover、Focus、Filled、Error、Disabled、Loading 状态。
- 错误文案说明问题和恢复方式，不能只显示“输入有误”。
- 长表单按业务主题分组，避免连续堆叠超过 8–10 个字段。

### 9.3 搜索与筛选

分为三级：

1. 关键词搜索：始终可见。
2. 高频筛选：始终可见，数量控制在 2–4 个。
3. 高级筛选：展开面板或 Drawer。

筛选后必须：

- 显示生效条件。
- 支持单项清除和全部清除。
- 展示结果数量。
- 保留用户返回时的筛选状态。

### 9.4 Table

- 表格用于比较、筛选和批量操作，不用于展示少量详情字段。
- 第一列应承载对象识别信息：名称 + 必要副标题。
- 数字右对齐；状态、日期和短文本保持一致对齐。
- 重要状态必须可快速扫描。
- 每行最多直接展示 1–2 个高频操作，其余进入更多菜单。
- 列数过多时优先固定关键列、允许列配置，不通过缩小字号硬塞。
- 冻结列是横向溢出时的辅助行为，不是常驻视觉：仅当表格内容宽度大于可用容器宽度时启用。
- 页面宽度足够、表格无需横向滚动时，冻结列恢复普通列布局，不显示固定定位、遮挡层或冻结阴影。
- 冻结状态变化不得改变列宽、排序、选择状态或当前滚动上下文。
- 表头和数据行使用 `color.table.divider` 作为浅横向分隔线；不得通过加深每行边框制造网格感。
- 表头可固定；分页与结果总数位于表格底部。
- 必须设计 Loading、Empty、No Result、Error、Partial Data 和 Permission Denied 状态。

### 9.5 Card 与 Panel

允许使用 Card 的场景：

- 独立经营指标。
- 可点击的对象或方案选择。
- 与相邻内容具有不同交互上下文。
- Dashboard 中需要明确边界的分析模块。

禁止使用 Card 的场景：

- 仅为了给标题和几行文字加边框。
- Card 内继续嵌套多层 Card。
- 表单中每个字段或数据项各自成卡。
- 详情页的所有章节统一卡片化。

强制检查：

- Card 内如果只有标题、两行文字和一个按钮，优先改为普通 Section。
- 相邻 Card 如果拥有相同背景、边框和交互上下文，应合并为一个 Section。
- 只用于制造浅色底和圆角的容器应删除。
- 团队成员、少量指标和最近动态不应默认各占一张 Card。
- 不得为了填满栅格创建内容价值不足的 Card。

### 9.6 Tabs

- Tabs 用于同一对象下并列且相互独立的内容维度。
- 不用 Tabs 表达线性业务流程。
- 标签应短、稳定，不使用长句。
- 状态数量可用 Badge 展示，但不得让数字压过标签含义。
- Tabs 超过 6 个时重新评估信息架构。

### 9.7 Status、Tag 与 Badge

- Status 表达生命周期或业务状态。
- Tag 表达属性和分类。
- Badge 表达数量或轻量提醒。
- 同一概念在全平台必须使用同一颜色和文案。
- 默认使用浅底色或描边，避免大面积实色。
- 风险等级需同时呈现等级文字和原因入口。
- 阶段百分比本身不分配独立颜色；颜色表达完成、当前、阻塞等语义，而不是 10%、25%、50%、90%。
- 同一对象在同一屏幕最多显示一个主状态 Tag 和一个独立风险状态；其余状态使用普通文字或放入详情。
- Avatar 使用真实头像、统一中性缩写样式或品牌蓝浅底；不得随机分配彩色或紫色头像。

### 9.8 Timeline 与阶段进度

Timeline 用于项目动态、评审记录、合同事件、交付事件：

- 时间。
- 事件标题。
- 操作者或责任人。
- 状态。
- 说明和附件。
- 必要的上下文操作。

阶段进度用于项目生命周期：

- 已完成、当前、待开始、阻塞必须可区分。
- 当前阶段显示开始时间、负责人、完成条件和下一行动。
- 不把阶段进度简化成一排普通 Tag。
- 阶段名称和流转规则必须来自正式 Business Rules。

### 9.9 Modal 与 Drawer

Modal 适合：

- 短表单。
- 确认操作。
- 单一对象的快速选择。
- 不超过一个主要决策的任务。

Drawer 或独立页面适合：

- 多分组长表单。
- 需要对照当前页面的编辑任务。
- 项目创建、合同录入、交付/出车计划等复杂任务。

禁止 Modal 叠加 Modal。必须保留用户上下文时，优先在原浮层中切换步骤或使用 Drawer。

### 9.10 Feedback 状态

所有页面和组件必须考虑：

- Loading：骨架或局部加载，避免整页闪烁。
- Empty：解释为何为空，并提供下一行动。
- No Result：说明筛选无结果，并支持清除条件。
- Error：说明影响范围和恢复方式。
- Disabled：说明不可用原因。
- Success：确认结果，并提示后续状态。
- Permission：说明缺少的权限和可联系角色。
- Partial Data：明确哪些数据不可用，不能伪装为 0。

提示条使用约束：

- 只有跨模块影响、需要立即处理或会阻止当前任务的问题才使用页面级 Alert。
- 正常流程说明、下一步提示和普通待办不使用全宽彩色 Alert。
- 同一页面首屏最多出现一个页面级 Alert。
- 同一问题不得同时通过 Alert、风险 Tag、摘要格和独立行动卡重复表达。

## 10. 数据可视化

### 10.1 图表选择

- 趋势：折线图或面积图。
- 分类比较：横向或纵向柱状图。
- 构成：仅在类别较少且差异明显时使用环图。
- 排名：水平条形图或排名列表。
- 进度：数字 + 进度条，必要时增加目标线。
- 关系：业务关系图或地图，但必须支持列表替代视图。
- 阶段：阶段进度条或 Funnel，仅在业务确实存在阶段转化时使用。

### 10.2 图表规则

- 每个图表必须有清晰结论或用户问题。
- 显示数据周期、单位和更新时间。
- Tooltip 中提供完整数值及必要比较。
- 颜色优先表达系列或状态，不作装饰。
- 同一页面图表色彩数量建议不超过 5 种。
- 项目阶段图例、漏斗数据、项目排行、车辆构成图例和车辆排行的主要可读文本统一为 12px；10px 只用于表头、单位、来源和辅助说明。
- 不能用图表表达的数据应使用数字、表格或文字。
- 不默认使用仪表盘；“项目健康度”必须同时解释构成与风险来源。
- 复杂关系图必须支持缩放、聚焦、搜索、图例和列表替代。

## 11. 业务专属 Pattern

### 11.1 项目健康度

项目健康度不是单个装饰性分数，应由已确认指标构成，例如进度、合同、交付、车辆、运营或回款风险。

组件至少包含：

- 总体状态。
- 主要风险来源。
- 变化趋势。
- 数据更新时间。
- 查看详情或处理入口。

具体计算模型待业务确认。

### 11.2 经营风险与异常中心

风险需包含：

- 风险类型。
- 严重程度。
- 影响对象。
- 发生或识别时间。
- 当前责任人。
- 处理状态。
- 建议动作或处理入口。

异常优先级不能只由颜色表达。

### 11.3 车辆状态

候选视觉状态：待交付、待投运、运营中、充电/换电、维修、停运、退役。

状态枚举、互斥关系与流转规则必须由业务文档确认后才能进入代码。

### 11.4 能源场站与补能

场站模块可表达：

- 场站身份与位置。
- 充电桩或换电工位能力。
- 当前可用能力。
- 排队或占用情况。
- 能耗与成本。
- 故障和维护状态。

地图不是默认答案；当用户主要比较经营指标时，列表或表格应优先。

### 11.5 业务关系视图

关系视图可表达：

```text
项目 → 客户 → 线路 → 车辆 / 车队 → 充换电场站 → 能源 → 运营结果
```

实际层级和关系必须以已确认数据模型为准。关系图用于理解与定位，不替代日常管理列表。

## 12. 基准页面模板

### 12.1 Dashboard

#### 用户目标

快速理解经营结果、项目推进和当前风险，并进入需要处理的事项。

#### 推荐结构

1. 页面标题、统计周期、更新时间和必要视图切换。
2. 5–7 个核心经营指标，包含同比/环比或目标差异。
3. 项目阶段分布、签约/交付/投运趋势、计划与实际。
4. 风险项目、超期事项、待审批和下一行动。
5. 区域、客户、车型、线路或能源结构等组合分析。

#### 原则

- 首屏形成“结果—风险—行动”闭环。
- 重要异常优先展示。
- 次要分析通过下钻处理，不无限向下堆模块。
- 每张图表都必须支持跳转到对应明细。
- 卡片尺寸由信息重要性决定，不追求平均铺满。

#### 必须覆盖的状态

- 正常数据。
- 部分数据缺失。
- 无数据。
- 加载失败。
- 统计周期切换。
- 用户仅有部分业务权限。

### 12.2 项目列表

#### 用户目标

查找项目、判断推进情况、识别风险并执行批量或单项目操作。

#### 候选字段

- 项目名称 / 客户。
- 区域与业务场景。
- 当前阶段。
- 项目负责人。
- 需求车辆数。
- 合同或预计经营金额。
- 下一里程碑。
- 风险状态。
- 最近更新时间。

以上仅为候选字段，需结合正式 Requirements 确认。

#### 推荐结构

1. 标题区与“新建项目”。
2. 阶段或关键业务视图 Tabs。
3. 搜索、高频筛选、视图保存和高级筛选。
4. 表格工具栏与批量操作。
5. 主表格、结果总数与分页。

#### 原则

- 表格是页面主体，减少外围 Card。
- 第一列同时展示项目名、客户或必要副信息。
- 阶段、风险、下一里程碑必须易于扫描。
- 行内只保留高频操作，其余进入更多菜单。
- 支持排序、固定关键列、列配置和保存视图。
- 返回列表时保留搜索、筛选、页码与滚动位置。

#### 必须覆盖的状态

- Loading。
- Empty。
- No Result。
- Error。
- 无创建权限。
- 批量选择。
- 批量操作部分成功。
- 超长项目名称和缺失字段。

### 12.3 项目详情

#### 用户目标

理解项目全貌、判断当前阶段和风险，并完成下一步推进。

#### 推荐结构

1. 扁平对象身份区：项目名称、客户、地区、业务场景、负责人；不使用外层 Card。
2. 紧凑事实摘要：车辆规模、金额、日期等使用非等宽分栏；不为每项创建 Card。
3. 单一项目阶段区：统一表达已完成、当前、待开始、阻塞和下一行动。
4. 必要时显示一个风险/阻塞提示；无真实异常时不占位。
5. 主 Tabs：概览、评审、合同、交付/出车计划、运营数据、项目动态。
6. Tab 内容使用扁平 Section、表格、Timeline 或描述分组，不重复卡片化。
7. 页面级操作：编辑、提交评审、更新阶段等，根据权限和状态显示。

Tabs 名称是候选结构，最终以业务范围为准。

#### 原则

- 顶部直接展示最关键状态，不藏入 Tab。
- 内容通过章节和分隔组织，避免 Card 套 Card。
- 当前阶段只在阶段区完整表达；Header 不再重复阶段百分比和完整阶段名称。
- 项目风险只保留一个主表达位置；阻塞时显示原因和处理入口，正常时不创建彩色风险 Card。
- 下一行动只设置一个主要入口，避免在摘要、提示条和概览中重复。
- 摘要字段按信息权重分配宽度，不使用机械的五等分或六等分栅格。
- 项目团队默认使用紧凑人员行、Avatar Group 或侧栏信息，不单独创建大 Card。
- 少量经营指标使用一条紧凑 Metrics Row，不把每项拆成卡片。
- 项目动态、评审和关键事件使用 Timeline。
- 合同、车辆、线路等大量数据使用表格或关联列表。
- 右侧摘要仅保留负责人、关键日期和下一行动等高价值信息。
- 页面操作必须随业务状态和权限变化。

#### 信息去重检查

完成页面后逐项检查：

- 当前阶段是否被完整重复超过一次。
- 风险是否同时出现在多个 Tag、摘要格和提示条。
- 下一行动是否出现多个同等级入口。
- 车辆数、金额和日期是否在首屏无理由重复。
- 同一说明文案是否在阶段区、Alert 和 Tab 内容中重复。

若答案为“是”，优先合并或删除，不通过修改文案制造表面差异。

#### 项目详情首屏容器上限

推荐保留：

1. 一个项目阶段与阻塞容器。
2. 一个当前 Tab 内容容器。

对象身份区、摘要事实和 Tabs 通过页面结构与分隔线组织，不再分别套 Card。

#### 必须覆盖的状态

- 正常推进。
- 阻塞或超期。
- 待审批。
- 无编辑权限。
- 部分关联数据缺失。
- 项目关闭或终止。
- 并发更新或数据已变化。

## 13. 响应式规则

### 13.1 宽屏与标准桌面

- `≥ 1440px`：完整顶部导航、展开侧栏、多列 Dashboard。
- `1200–1439px`：保持主要布局，减少次要列宽和模块并列数量。
- `1024–1199px`：默认收起侧栏，Dashboard 从 4 列降为 2 列，详情侧栏移入主内容。

### 13.2 小屏策略

- 不通过无限缩小字号维持桌面布局。
- 表格保留关键列，其他字段进入详情或列配置。
- 工具栏允许换行，主操作保持可见。
- 复杂关系图提供列表模式。
- 若移动端不属于产品范围，应明确最低支持宽度并提供友好提示。

## 14. 可访问性

- 正文和背景对比度目标不低于 WCAG AA。
- 所有交互支持键盘操作与清晰 Focus。
- 图标按钮具有可访问名称和 Tooltip。
- 点击目标建议不小于 32×32px；主要操作优先 40px 高度。
- 状态同时使用文字、颜色和必要图标。
- 表单错误与对应字段建立程序化关联。
- 图表提供文字摘要、数据表或可读取替代内容。
- Loading、成功、失败和异步状态变化需要向辅助技术传达。
- 页面在 200% Zoom 下仍应保持可读和可操作。

## 15. Do / Don't

### Do

- 使用真实、接近生产密度的业务数据验证设计。
- 使用排版、间距和对齐建立层级。
- 突出风险、阻塞和下一行动。
- 让同类页面共享相同骨架和组件。
- 为每个核心组件实现完整状态。
- 让图表支持查看明细和解释数据。
- 使用新能源重卡业务专属图标与 Pattern。

### Don't

- 不使用大面积渐变背景。
- 不使用玻璃拟态。
- 不使用彩色阴影。
- 不给每个模块都套 Card。
- 不嵌套多层 Card 或 Modal。
- 不用大量彩色卡片填满 Dashboard。
- 不滥用环图、仪表盘和无业务结论的图表。
- 不使用无意义图标或 Emoji。
- 不使用过大的圆角。
- 不使用紫色、Violet、Lavender、Magenta 或蓝紫渐变。
- 不生成紫色字母 Logo、紫色 Avatar 或随机彩色团队头像。
- 不把项目阶段百分比做成多色胶囊标签。
- 不用机械等宽卡片排列语义权重不同的字段。
- 不在同一屏幕重复展示阶段、风险和下一行动。
- 不为正常流程说明创建全宽彩色 Alert。
- 不把页面做成传统 Ant Design 模板的直接翻版。
- 不为了填满空间增加无业务价值内容。
- 不擅自改变业务规则、字段、状态或权限。

## 16. Codex 实现规则

Codex 在修改或新增页面前必须：

1. 阅读 Product Context、Requirements、Business Rules、User Flow、Interaction Spec 和本规范。
2. 检查真实技术栈、目录结构、现有组件、Token、全局样式和 UI Library。
3. 查找与目标页面最相近的现有页面与组件。
4. 区分已确认规则、当前假设和待确认问题。
5. 未确认的业务规则不得直接写入代码。
6. 从参考截图中选出与目标页面最相关的 2–3 张，写出布局、颜色、容器、密度和组件映射。
7. 检查项目中是否存在 Purple、Violet、Lavender、Magenta、紫色渐变或紫色阴影；记录需要重新映射的位置。

实现过程中必须：

- 优先修改和复用现有组件，不无必要重写。
- 优先映射现有 Token，不创建重复颜色、间距和圆角。
- 不随意新增依赖或改变技术栈。
- 不因“更美观”修改业务流程、字段、权限和状态。
- 没有对应规范时，沿用最接近的 Pattern，不自由创造新的视觉语言。
- 保留 Loading、Empty、Error、Disabled、Success、Permission 和边界状态。
- 使用 Semantic HTML，处理 Keyboard、Focus、响应式和性能。
- 使用真实或具有真实密度的模拟数据验证布局。
- 颜色必须来自本规范白名单；不得使用组件库默认紫色或自行增加紫色色值。
- 页面结构必须满足容器预算和信息去重规则。
- 未提供正式 Logo 时，不得生成字母 Monogram 作为替代品牌。

视觉 QA 必须：

1. 在相同视口和浏览器 100% 缩放下分别截取参考图与实现图。
2. 将两者并排比较页面骨架、导航比例、容器数量、颜色、字号层级、边框、圆角和内容密度。
3. 检查代码中是否残留紫色 Token、类名、硬编码色值或渐变。
4. 检查首屏一级圆角容器数量是否超过预算。
5. 检查阶段、风险、下一行动和核心事实是否重复。
6. 修正可见差异后再次截图比较；只检查一次不算完成。

完成后必须说明：

- 修改了哪些文件。
- 为什么修改。
- 是否新增依赖。
- 如何运行。
- 如何验证。
- 是否存在待确认问题。

## 17. 基准页面实施顺序

1. Dashboard。
2. 项目列表。
3. 项目详情。

## 21. 云管理后台参考增量规则（V1.5）

来源：`租户运营转化率 UI.sketch`、`SASE 云租户管理平台 UI.sketch`。详细源数据与提取边界见同目录 `cloud-platform-sketch-extraction.md`。本节为迁移规则，不代表源文件提供了完整组件库或运行交互。

### 21.1 字体与密度

- 用户已确认口径不变：网页常规文字 12px；除纯数字内容外，任何文字不得低于 10px。
- 源后台文本图层主要为 PingFang SC 13px，运营分析主要为 14px。项目名称、关键行、详情内容可以使用 13–14px；不要把“常规 12px”理解为所有文字必须统一 12px。
- 10px 仅承载低优先级辅助信息，不用最小字号表达正文、任务或关键状态。
- 高密度优先通过减少重复内容、合理列宽和收敛间距实现，不通过缩小正文实现。
- 字号验收检查浏览器 computed font-size，包括继承、rem 换算、图表 canvas / SVG 标签和组件内部样式，不只搜索 CSS 字符串。页面缩放、transform 和截图缩放需分别记录。

### 21.2 容器与控件

- 标准控件继续优先复用项目既有组件。36px 可作为常规控件候选高度；28–32px 仅用于紧凑工具栏且需检查点击目标。
- 控件圆角优先 4px；分析容器圆角可用 6px，与现有 Token 一致。不能把源文件所有矩形尺寸直接作为按钮或表格行高。
- 边框以 1px、低对比度中性灰为主。源稿高频值为 #E0E0E0 / #DFE1E6，接入项目时映射到既有语义边框 Token，不新增同义 Token。
- 分析容器轻阴影参考 `0 2px 8px rgba(0,0,0,.08)`，浮层参考 `0 4px 10px rgba(0,0,0,.10)`；常规区块优先弱边框，不要求每张 Card 都有阴影。

### 21.3 列表与详情

- 列表工具栏组织搜索、筛选和主操作；批量操作与单行操作有明确归属。
- 重点列优先保持可读：项目/客户名称、状态、负责人、关键日期。普通行不变成独立圆角 Card。
- 详情按任务分区，而不是按视觉组件堆叠。信息、记录、附件和操作各自有明确位置。
- 沟通与操作记录展示人员、时间、内容、附件；编辑和删除权限必须来自正式业务规则。
- 不复制租户授权、付费意愿、安装包等业务字段，目标字段以正式 Product Context 为准。

### 21.4 经营分析图表

- 指标摘要回答“当前多少”，趋势回答“如何变化”，漏斗回答“在哪个环节流失”，排行回答“对象之间如何比较”。按分析任务选择，不为填满栅格重复显示同一指标。
- 趋势、转化漏斗和排行均是候选 Pattern，不是新增业务需求。阶段、分母、统计周期、计算口径和权限过滤必须先确认。
- 漏斗必须说明连续流程与统计对象；互不连续的状态分布不要强行画成转化漏斗。
- 图表使用真实单位、标签、图例和可解释的空/错误状态，禁止初稿占位数据进入正式业务。
- 源稿出现紫色图表系列，目标仍遵守紫色禁用规则；使用经确认的非紫色图表色板，图例不得只靠颜色区分。

### 21.5 来源与实施边界

- 两份源文件的页面主要由普通图层组构成，没有检测到可直接迁移的本地 Symbols 组件体系。
- 1440 / 1614px 是设计组尺寸，不是已确认响应式断点。
- 不自动导入历史备份、零散图层、初稿统计数据或未经授权的图标资产。
- 源数据读取不等于原生渲染验证；推广到新页面前仍需同视口截图、计算样式、键盘与真实数据回归检查。

## 22. SDP 科技感参考增量规则（V1.6）

来源：`SDP 科技感 20240903.sketch`。提取证据见同目录 `sdp-tech-sketch-extraction.md`。只迁移可复用模式，不导入 SDP 网络、安全、主备或监控业务。

### 22.1 检索、标签与视图

- 搜索字段和筛选条件分别表达；已有条件可见、可移除，并提供清空入口。筛选字段与统计结果保持一致。
- 全局检索与当前页面检索范围明确，不混用同一个不带说明的搜索框。
- 标签优先复用现有组件，标签维护权限和业务枚举需确认；标签不是随机配色装饰。
- 当同一数据提供列表/分析视图时，保留筛选、统计周期和对象范围；切换不无故重置上下文。
- 日志/消息展示事件、对象、发生时间与详情入口；根据正式权限决定可见内容，不将技术文本直接当作用户任务。

### 22.2 基础、悬停与选中

- 可交互容器分别定义 base、hover、selected、disabled、focus 状态；后两项为目标实现要求，不宣称源稿完整提供。
- hover 轻量强调可操作性；selected 表示持续的选择状态，不能只有鼠标悬停时才显示。
- 键盘 focus 可见，不只提供鼠标 hover。
- 使用语义化 Token 映射弱边框、浅背景和选中强调，不新增一次性渐变样式。

### 22.3 关系图与监控

- 关系图仅在关系解释比列表更有效时使用。节点、分组、连线和图例必须对应真实数据。
- 场站、充电桩、车辆和线路的关系、数量、状态、更新频率与权限必须先确认，不由 Codex 自行建立。
- 节点提供名称、状态与详情入口；告警同时用文字表达，不只靠颜色或连线效果。
- 大量节点需要分组、筛选、缩放或展开策略，并提供列表替代入口；不要通过不断缩小文字容纳节点。
- 关系图不等于地图；车辆地理位置与路线需单独确认地图能力。
- “在线”“运行中”“充电中”“故障”含义不可混用，采用已确认业务枚举。

### 22.4 科技感边界

- 普通经营页继续沿用已确认蓝色、弱边框、小圆角和低装饰结构。
- 渐变、亮色发光、动态图形和展示型数字字体不是默认 Token；需要展示或监控大屏时单独确认。
- Sketch 共享色板中的“主色”历史名称不能覆盖目标品牌决策；多个 A/B/C 设计组也不能自动决定目标方案。
- 非数字文字最低 10px、常规 12px 的用户要求与紫色禁用规则保持不变。

### 23.3 统计摘要与单位

- 项目列表顶部采用 5 列统计卡：当前范围项目、需求车辆、已交付车辆、需求挂车、已交付挂车。字段含义和计算规则来自需求基线，本节只约束视觉。
- 统计卡标签使用 12px 次级文字；核心数字使用 22px/600，并启用等宽数字特性。
- 常规统计卡单位使用 12px/400、次级文字色，与数字保持 4px 间距。
- 项目详情的紧凑车辆统计中，核心数字与单位分层；单位使用 10px/400，不与核心数字争夺视觉权重。
- 项目、需求车辆/挂车、已交付车辆/挂车使用一致的图标底板结构，通过蓝、橙、绿表达对象类别和正向结果。
- 单位字号调整属于纯视觉规则，不改变数量口径。

### 23.4 项目统计图表

- 项目阶段分布图例、阶段名称和数量统一使用 12px。
- 累计转化漏斗中的阶段名称、累计数量和转化率统一使用 12px；列标题和辅助说明允许使用 10px。
- 项目数量排行中的项目名称和数值统一使用 12px；序号底板保持紧凑，不放大为独立状态组件。
- 图表标题使用 14px/600，辅助说明使用 11px；图表内容不得通过低于规范字号来压缩布局。
- 项目阶段图例的 Hover/Selected 使用品牌浅蓝背景与品牌蓝文字；阶段本身的业务含义和筛选行为由交互规则决定。

### 23.5 车辆分析模块

- 牵引车与挂车分析模块采用“构成环图 + 图例”和“排行列表”两种固定 Pattern。
- 构成图例的车型/车辆类型名称、数量和比例统一使用 12px；图例色点为 8px。
- 排行列表中的对象名称与车辆数统一使用 12px；排行序号可根据密度使用 11–13px。
- 分析模块标题使用 13px/600，数据来源或完整度说明使用 10px。
- 车型、地区、品牌型号和数量的统计口径不由 Design Spec 定义。

### 23.6 资料卡片

- 客户资料和项目资料复用同一资料卡骨架：资料类别、上传状态、文件信息、操作区。
- 已上传文件名使用 14px/600、主文字色，并执行单行截断；完整文件名通过原生标题或等效可访问方式提供。
- 文件大小、上传人和上传时间使用 11px、次级文字色。
- 未上传卡片中的上传提示使用 12px，格式和大小说明使用 10px。
- 已上传卡片的操作在指针设备上可于 Hover/Focus 时显现；无 Hover 的设备必须直接显示操作。操作权限仍由业务规则决定。

### 23.7 表格与冻结列

- 所有桌面表格的表头和数据行横向分隔线使用 `#EDF0F4`，比常规容器边框更浅。
- 行 Hover 使用极浅蓝背景，不通过加深横线表达悬停。
- 表头高度为 40px，常规数据行高度为 48px；紧凑业务表格需另行说明。
- 第一列或关键列只有在容器实际出现横向滚动时才进入冻结状态。
- 页面宽度足以完整显示表格时，冻结定位、冻结层级和右侧阴影全部关闭。
- 冻结列启停以真实布局测量结果为准，不仅依据固定断点判断。
- 移动端若切换为卡片式行布局，则不沿用桌面冻结列表现。

“冻结列仅在横向溢出时出现”会影响用户浏览行为，需要同时同步至 Interaction Spec / User Flow；其余边框颜色与行高属于 Design Spec。

### 23.8 图标与离线预览

- 原型交付包必须支持通过 `file://` 直接打开，不以本地开发服务器为前提。
- 项目统计等关键图标采用内嵌 SVG 或经过验证的本地相对资源。
- 不使用可能因浏览器本地文件安全策略失效的外部 CSS Mask 作为关键图标的唯一呈现方式。
- 图标资源加载失败时应保留可识别的文本语义，不得只出现无内容的彩色底板。
- 该规则属于设计资产与交付兼容规范，不改变业务逻辑。

### 23.9 业务交互同步边界

以下已在原型中出现，但不属于纯视觉规范，必须以最新需求基线和 Interaction Spec 为准：

- 已交付数量的数据来源与自动汇总口径。
- 已交付数量大于 0 时的页面跳转。
- 已交付数量为 0 时不可点击。
- 项目列表新增的需求/交付数量列。
- 项目详情、车辆管理和关联项目之间的数据联动。
- 表单字段增删、跟进记录内容、资料类别、权限和必填规则。

Design Spec 只规定上述元素的可见层级、可点击态、禁用态、Focus 和响应式表现，不决定其业务条件。

### 23.10 当前差异与待治理项

- 当前原型个别库存状态标记仍存在紫色色值，与本规范的紫色禁用规则冲突。V2.0 不自动修改代码；在下一次视觉 QA 中应先确认其业务语义，再映射到允许的状态色。
- 当前原型包含面向小屏的布局降级样式，但桌面端最低支持宽度仍未形成正式产品约束，保持待确认。
- 当前原型中的 Demo 数据、统计值和资料文件名只用于展示密度，不作为正式业务数据定义。
